# S3-compatible

Stores artifacts in an S3 bucket, either on AWS or on any service that speaks the S3 API.

- Kind: `s3`
- Needs: a bucket, an endpoint for anything that is not AWS, and an access key and secret key
  unless the host already has AWS credentials of its own

Backvault uses the AWS SDK and uploads with multipart upload, 16 MiB parts by default, so object
size is limited by the provider rather than by memory. Tested providers and their exact settings
are listed in [S3 providers](s3-providers.md).

## Configuration fields

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `endpoint` | string | no | empty | Base URL of the service, for example `https://s3.eu-central-1.wasabisys.com`. Leave empty for AWS, which is then derived from `region`. Must be a full URL with a scheme. |
| `region` | string | no | `us-east-1` | Region used for request signing. Some providers ignore it, but Signature V4 still requires a value. Cloudflare R2 uses `auto`. |
| `bucket` | string | yes | none | Bucket name. Backvault does not create the bucket. |
| `prefix` | string | no | empty | Key prefix inside the bucket, for example `backvault/prod`. Leading and trailing slashes are ignored. |
| `access_key` | string | no | empty | Access key id. Leave both key fields empty to use the ambient AWS credential chain: environment, shared config, instance role. |
| `secret_key` | secret | no | empty | Secret access key. Stored encrypted, returned as `********`. |
| `path_style` | bool | no | `false` | Address the bucket as `endpoint/bucket/key` instead of `bucket.endpoint/key`. Required by MinIO and by any endpoint without wildcard DNS. |
| `storage_class` | select | no | empty | One of empty, `STANDARD`, `STANDARD_IA`, `ONEZONE_IA`, `INTELLIGENT_TIERING`, `GLACIER_IR`, `GLACIER`, `DEEP_ARCHIVE`. Empty uses the bucket default. Archive classes are slow or expensive to read back. |
| `sse` | select | no | `none` | Server-side encryption: `none`, `AES256` for provider managed keys, or `aws:kms`. Independent of Backvault's own age encryption. |
| `sse_kms_key_id` | string | no | empty | KMS key id or ARN. Only shown when `sse` is `aws:kms`, and only sent then. Leave empty to use the bucket's default KMS key. |
| `part_size_mb` | int | no | `16` | Multipart part size in MiB, minimum 5. Larger parts mean fewer requests and more memory per upload. |
| `concurrency` | int | no | `4` | How many parts are uploaded in parallel, between 1 and 64. |
| `skip_tls_verify` | bool | no | `false` | Accept any TLS certificate from the endpoint. Only for self-signed endpoints on a trusted network. |

`secret_key` is the only secret field. Sending exactly `********` back in an update keeps the
stored value, so you can edit a destination without retyping the key.

`access_key` and `secret_key` go together: set both, or neither. Setting only one is refused
when the destination is saved, because it is almost always a half-finished edit rather than a
deliberate choice. `part_size_mb`, `concurrency` and `skip_tls_verify` sit in the advanced part
of the form.

## Example

A destination as it appears in a `backvault export` document:

```yaml
destinations:
  - name: Offsite bucket
    kind: s3
    description: Wasabi eu-central-1
    config:
      endpoint: https://s3.eu-central-1.wasabisys.com
      region: eu-central-1
      bucket: acme-backups
      prefix: backvault/prod
      access_key: AKIAEXAMPLE
      secret_key: '********'
      path_style: false
      storage_class: ''
      sse: AES256
    tags:
      - offsite
```

## How Backvault writes objects

The object key is the prefix followed by the artifact path:

```text
<prefix>/<jobSlug>/<jobSlug>-<YYYYMMDD>-<HHMMSS>.<ext>[.gz|.zst][.age]
```

The timestamp is UTC. A job with slug `db-prod`, prefix `backvault/prod`, zstd compression and age
encryption writes:

```text
backvault/prod/db-prod/db-prod-20260917-020000.dump.zst.age
```

Uploads use multipart upload with `part_size_mb` parts, 16 MiB by default, and `concurrency`
parts in flight at a time, four by default. A multipart upload is only visible as an object once
it is completed, so a cancelled or failed run leaves no readable object under the final key.
Backvault asks the SDK to abort the upload when a part fails, so an ordinary failure cleans up
after itself, but a process that is killed outright can still leave parts behind, and most
providers bill for them. Add a lifecycle rule that aborts incomplete multipart uploads after a
few days:

```json
{
  "Rules": [
    {
      "ID": "abort-incomplete-multipart",
      "Status": "Enabled",
      "Filter": { "Prefix": "" },
      "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 3 }
    }
  ]
}
```

Deleting an object that does not exist is not an error, which is what S3 itself does, so
retention is safe to re-run.

`List` is used by retention and by the destination browser, `Stat` by verification. `Stat` is a
`HeadObject`, and verification compares the size it reports with the size Backvault recorded,
nothing else. No checksum is compared against the provider: a bare ETag of a multipart upload is
not the MD5 sum of the object, so it would not be comparable anyway. The sha256 Backvault stores
for the artifact is the integrity check, and a download is verified against it.

## Permissions

The credential needs to write, read, delete and list within the prefix. On AWS, this is the
minimum policy for a bucket named `acme-backups` and prefix `backvault/prod`:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ListWithinPrefix",
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::acme-backups",
      "Condition": {
        "StringLike": { "s3:prefix": ["backvault/prod/*", "backvault/prod"] }
      }
    },
    {
      "Sid": "ReadWriteObjects",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:DeleteObject",
        "s3:AbortMultipartUpload",
        "s3:ListMultipartUploadParts"
      ],
      "Resource": "arn:aws:s3:::acme-backups/backvault/prod/*"
    }
  ]
}
```

`s3:ListBucket` is on the bucket, not on the objects, which is a common source of access denied
errors during retention. `s3:AbortMultipartUpload` is needed so a failed upload can clean up
after itself.

The connection test writes nothing. It calls `HeadBucket`, and if that is denied it falls back
to listing a single key under the prefix, so a credential that passes the test can still fail
on the first upload if `s3:PutObject` is missing.

If the bucket enforces server side encryption with a KMS key, or you set `sse` to `aws:kms`,
add `kms:GenerateDataKey` and `kms:Decrypt` on that key, otherwise uploads fail with access
denied even though the S3 policy is correct. `sse_kms_key_id` picks the key; left empty, the
bucket's default KMS key is used.

Drop `s3:DeleteObject` if you want an append only destination. Retention then fails for that
destination and the run is marked `warning`. Consider whether an object lock or a lifecycle
rule on the provider side is a better fit than Backvault retention. See
[retention](../retention.md).

## Using S3 from the standalone scripts

`scripts/upload-s3.sh` and `scripts/prune-s3.sh` cover hosts that push straight to storage
without a Backvault destination. They take the same settings as environment variables:

```bash
export S3_ENDPOINT=https://s3.eu-central-1.wasabisys.com
export S3_REGION=eu-central-1
export S3_BUCKET=acme-backups
export S3_PREFIX=backvault/prod/db-prod
export S3_ACCESS_KEY=AKIAEXAMPLE
export S3_SECRET_KEY=...
export S3_PATH_STYLE=auto

scripts/upload-s3.sh --file /var/tmp/db-prod-20260917-020000.dump.zst
scripts/prune-s3.sh --keep 14
```

The scripts prefer the `aws` CLI, then `mc`, and fall back to a built-in AWS Signature V4
implementation written in bash with curl and openssl. The built-in uploader was tested against
MinIO: PUT, GET, ListObjectsV2 with a prefix and a continuation token, and DELETE all sign
correctly. It performs a single PUT, so it cannot upload more than 5 GiB in one object. For
larger artifacts install the `aws` CLI or `mc` on that host. Credentials are never passed on a
command line. See [scripts](../scripts.md).

`S3_PATH_STYLE=auto` turns path style on whenever an endpoint is set that is not an AWS
endpoint, which is the right default for MinIO and for most self-hosted gateways.

## Gotchas

- **Path style versus virtual host style.** MinIO and most on-premises gateways need
  `path_style: true`. Virtual host style requires wildcard DNS for `*.endpoint`, which a bare IP
  address or a plain hostname does not have. A wrong setting shows up as a DNS failure or as a
  404 on a bucket that exists.
- **The region still matters when the provider ignores it.** Signature V4 signs the region into
  the request. Providers that accept any region still reject a signature computed for a
  different one, so use the value the provider documents.
- **Cloudflare R2 uses `auto`.** It has no storage classes. See
  [S3 providers](s3-providers.md).
- **Backblaze B2 needs the S3 compatible endpoint.** The native B2 API is a different protocol
  and does not work with this driver.
- **Object lock and versioning change what retention does.** With versioning on, a delete adds
  a delete marker instead of freeing space, and old versions keep costing money until a
  lifecycle rule removes them. With object lock in compliance mode, retention cannot delete at
  all and the run ends as `warning`.
- **Glacier classes are not readable on demand.** An artifact written with a deep archive
  storage class has to be restored at the provider before Backvault can download it, and
  verification fails against it in the meantime. Use an instant retrieval class if you want
  restores to work without a thaw step.
- **Server-side encryption is a choice of three, not a switch.** `sse` takes `none`, `AES256` or
  `aws:kms`, and anything else is refused when the destination is saved. Only `aws:kms` reads
  `sse_kms_key_id`, and only AWS accepts that mode at all: on MinIO, B2, Wasabi, R2 and Hetzner
  leave `sse` at `none` and encrypt with age instead, see [encryption](../encryption.md).
- **Empty credentials are not an error.** With `access_key` and `secret_key` both empty, the AWS
  SDK falls back to its own chain: `AWS_ACCESS_KEY_ID` and friends in the environment of the
  Backvault process, `~/.aws/config`, or the instance role. That is what you want on EC2 and a
  surprise everywhere else, where the test then fails with a missing-credentials error.
- **Prefixes are not directories.** Removing every artifact under a prefix leaves nothing behind
  in the bucket, and the destination browser then shows an empty prefix rather than a missing
  one. That is normal.
- **Credentials in the panel are write only.** Once saved, the secret key is returned masked.
  Rotating the key means pasting a new one, there is no way to read the old value back out of
  Backvault. See [security](../security.md).
